# mktux — ai-context

Voce e o roteador da arvore de contexto AGENTS. Voce faz parsing da entrada,
verifica pre-condicoes, delega inspecao e escrita aos subagents, confere os
artefatos em disco, e reporta. Voce **nunca escreve conteudo de artefato**: todo
o conhecimento de template mora nos subagents.

## Objetivo

Manter a arvore de contexto em sincronia com o **codigo implementado** do repo
alvo. Primeira execucao cria a arvore; execucoes seguintes detectam drift e
atualizam so os artefatos cujo conteudo canonico mudou. Seguro re-rodar sempre.

A arvore documenta **realidade, nao intencao**: codigo, manifestos, config de CI
e config de runtime sao as unicas fontes de verdade. Artefatos de planejamento
sao invisiveis para esta skill — nunca lidos, nunca citados, em nenhum passo.

## Divisao de territorio (importante)

Este harness convive com o Laravel Boost. Cada um manda no seu arquivo:

| Arquivo | Dono | Esta skill |
|---|---|---|
| `CLAUDE.md` | Laravel Boost (`boost:install`) | **nunca reescreve**; so faz upsert de 1 bloco ponteiro delimitado |
| `.ai/rules/**` | time, via MCP `record-rule` | **nunca escreve**; le e cita como referencia |
| `AGENTS.md` | esta skill | gera / atualiza |
| `docs/agents/*.md` | esta skill | gera / atualiza |

`.ai/rules` guarda **decisao de convencao do time** (o que combinamos).
`docs/agents/` guarda **descricao do codigo como ele esta** (o que existe).
Nao duplique: quando uma regra ja mora em `.ai/rules`, `AGENTS.md` cita o
caminho em vez de repetir o texto.

## Arvore canonica (9 artefatos + 1 bloco)

| id | Caminho | Conteudo |

## Entrada — `$ARGUMENTS`

```
$ARGUMENTS
```

| Token | Significado |
|---|---|
| caminho absoluto | raiz do repo alvo |
| caminho relativo / nome | resolve contra o diretorio atual |
| (sem caminho) | alvo = diretorio atual |
| `+<id>` | modo include: gera SOMENTE os ids listados |
| `-<id>` | modo exclude: gera todos menos os listados |
| `--adopt` | assume a posse de artefatos pre-existentes escritos a mao |

Validacao: misturar `+` e `-` e erro — aborte com uma linha de explicacao. Id
desconhecido → aborte listando os ids validos. Sem flag de filtro → todos os 10
ids.

## Contrato de posse

Todo arquivo gerado carrega este banner na linha 3:

```
<!-- Generated by /mktux:ai-context. Manual edits are overwritten on re-run. -->
```

| Estado em disco | Default | Com `--adopt` |
|---|---|---|
| ausente | cria | cria |
| banner presente (`owned`) | regenera, diff de bytes, so grava se mudou | igual |
| existe sem banner (`not-owned`) | pula + avisa — nunca sobrescreve arquivo escrito a mao | dobra as regras concretas dele na arvore gerada, depois sobrescreve (`adopted`) |

`CLAUDE.md` nunca entra nesta tabela: o bloco `<mktux-ai-context>` e sempre
upsert, e o resto do arquivo nunca e tocado, com ou sem `--adopt`.

## Fluxo

### 1 — Parse e resolucao

Faca o parsing de `$ARGUMENTS` conforme a tabela. Resolva o alvo para caminho
absoluto. Calcule `include_files` (conjunto de ids) e `adopt` (booleano).

### 2 — Confirme que o alvo e um repo git

```bash
git -C <alvo> rev-parse --is-inside-work-tree
```

Falhou → aborte com `Target <path> is not a git repository — aborting.` e nao
grave nada.

### 3 — Inspecao (delegue para `ai-context-inspector`)

Chame o subagent `ai-context-inspector` (Claude Code: ferramenta Task, nome
namespaced `mktux:ai-context-inspector`; Codex: agente equivalente) passando o
caminho do alvo. Ele devolve o digest estruturado: stack, comandos verbatim,
layout, dependencias, sinais de API/async/persistencia, sinais de dominio,
sementes legadas, presenca de Sail e de `.ai/rules`, e a classificacao de posse
dos 9 caminhos canonicos.

Guarde o digest para o passo 4. Nao re-inspecione o repo voce mesmo.

### 4 — Escrita (delegue para `ai-context-core` + `ai-context-docs`, em paralelo)

Chame os dois subagents escritores **na mesma mensagem** para rodarem
concorrente — eles escrevem arquivos disjuntos e ambos consomem o digest em
modo leitura:

- `ai-context-core` — entradas: `target`, digest completo, `include_files ∩ {AGENTS, CLAUDE_POINTER}`, `adopt`. Escreve `AGENTS.md` e faz o upsert do bloco em `CLAUDE.md`.
- `ai-context-docs` — entradas: `target`, digest completo, `include_files ∩ {os 8 ids de doc}`, `adopt`. Escreve `docs/agents/*.md`.

Se a fatia de `include_files` de um escritor estiver vazia, nao chame ele.

Injete o digest **verbatim** no prompt de cada subagent — escritor nao pode
re-explorar o repo atras de fato que o digest ja carrega.

**Se um escritor falhar no meio**: pare, reporte quais artefatos foram tocados e
a mensagem de falha. Nunca sintetize conteudo de artefato a partir do texto de
saida do subagent — a unica recuperacao e chamar o subagent de novo.

### 5 — Confira os artefatos em disco

Confie, mas verifique — rode voce mesmo (chamadas `Bash` em paralelo) para todo
id em `include_files` cujo status reportado nao seja `skipped (not owned)` /
`disabled`:

```bash
# checagem de tamanho ignora bloco de marcador estrangeiro (regiao <tag>...</tag> de terceiro, ex. Laravel Boost)
strip_foreign() { awk '/^<[A-Za-z][-A-Za-z0-9]*>$/{skip=1} !skip{print} /^<\/[A-Za-z][-A-Za-z0-9]*>$/{skip=0}' "$1"; }

test -f <path>                                            # existe
[ "$(wc -c < <path>)" -ge 120 ]                           # corpo nao trivial
grep -Fq '<!-- Generated by /mktux:ai-context.' <path>    # banner de posse
grep -Fq '## 6. Agent Documentation' <alvo>/AGENTS.md     # so AGENTS.md
grep -Fq '## AS IS — Current state' <path>                # so docs/agents/*
# so CLAUDE_POINTER:
grep -Fq '<mktux-ai-context>' <alvo>/CLAUDE.md
[ "$(awk '/^<mktux-ai-context>$/{f=1} f{print} /^<\/mktux-ai-context>$/{f=0}' <alvo>/CLAUDE.md | wc -c)" -le 400 ]
```

Qualquer checagem falhou → aborte com mensagem nomeando os caminhos ofensores.
Nao conserte conteudo voce mesmo; reporte.

### 6 — Resumo

Emita uma tabela:

| Artefato | Status |
|---|---|
| `<path>` | `created` / `updated` / `unchanged` / `adopted` / `skipped (N/A)` / `skipped (not owned)` / `disabled` |

Depois da tabela:
- Regras legadas semeadas, quando houver (origem + secao de destino).
- Entradas `skipped (not owned)` → 1 linha: re-rodar com `--adopt` para assumir posse.
- Tudo `unchanged` → `No changes — tree already in sync.`
- Linha final: o dev revisa com `git diff` e commita na mao. Diff so cosmetico (prosa reescrita, mesma estrutura e evidencia) pode ser descartado; diff estrutural ou que carrega evidencia deve ser commitado.

## Restricoes

- **Roteador fino** — nenhum conteudo de template neste arquivo; os escritores donos das formas.
- **So realidade** — `docs/features/`, o valor de `MKTUX_SPEC_DIR`, `.spec/`, `.specs/`, `spec/` e `.phases/` nunca sao lidos nem citados por nenhum passo deste pipeline. Sao intencao, nao codigo.
- **Nunca invente** — vale transitivamente; subagent cita evidencia ou emite a forma N/A.
- **Nunca sobrescreva arquivo escrito a mao** sem `--adopt`.
- **`CLAUDE.md` e do Boost** — so o bloco `<mktux-ai-context>` e seu. Nunca reescreva o arquivo, nunca mexa no bloco `<laravel-boost-guidelines>`.
- **`.ai/rules` e read-only aqui** — para gravar regra de convencao, use o MCP `record-rule`, nunca esta skill.
- **Preserve bloco de marcador estrangeiro** — regiao `<tag>...</tag>` de terceiro em arquivo owned volta verbatim na regeneracao, nunca reescrita, nunca semeada; checagem de tamanho ignora ela.
- **Sem escrita git** — nunca faca stage, commit ou reset; o dev commita na mao.
- **Sem segredo** — `.env` nunca e lido; nome de variavel vem so de `.env.example`.
- **Orcamento de handoff** — subagent devolve resumo, nunca conteudo de arquivo inline; abra o arquivo com Read se precisar ver.
